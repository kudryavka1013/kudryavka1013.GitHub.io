文档笔记迁移与发布

发表于 2026-02-24 分类于 笔记 ， 博客搭建

本文记录了将博客笔记文档与部署代码仓库分离的过程，部分借助 AI 实现，权当参考。

前言

原先仅是总结一些前端的学习笔记，因此直接使用 VSC 在代码仓库里编辑和发布。后来接触了 Obsidian 后，才发现原来除了使用云笔记方案之外，也可以把文档维护在自己的 GitHub 上，真是妙哉（之前我怎么没想到），于是便开始了折腾之旅。

笔记逐渐多起来之后，发现同时维护笔记仓库和博客仓库的文档，是一件挺麻烦的事。把笔记整理成文章，需要来回复制；并且文字内容放在不同的地方，让我有点不爽（强迫症犯了）。于是便想能否将博客的内容搬到笔记仓库中去。

现状

目前使用的是 Hexo 引擎，文档是放置在 A 仓库的 source 目录下，当 A 仓库有 commit 时，github actions 会自动触发部署动作，检出仓库并执行部署命令。

我想要的效果是笔记放在 B 仓库，笔记有更新时让 A 仓库读取 B 仓库的文件，把文档复制过去，然后执行原有的步骤。那么核心问题就是 A、B 仓库之间的监听和读取了。

方案

执行流程大概如下：

  1. 仓库 B (文档)：当有代码推送时，通过 Action 向仓库 A 发送一个信号（Repository Dispatch）。
  2. 仓库 A (博客)：接收到信号后，启动构建任务。
  3. 仓库 A 的构建脚本：
    • 检出仓库 A 的代码（Hexo 环境）。
    • 检出仓库 B 的代码（Markdown 文档）。
    • 将 B 的文档移动到 A 的特定目录下。
    • 执行部署操作。

具体步骤

1. 访问权限

由于涉及到跨仓库触发和读取私有仓库，需要一个 Personal Access Token (PAT)。

  1. 在 GitHub 设置中生成一个 PAT (Classic)，勾选 repo 权限。
  2. 将这个 Token 保存到仓库 B 的 Settings -> Secrets and variables -> Actions 中，命名为 BLOG_ACCESS_TOKEN，用于仓库 B 访问仓库 A 的文件。
  3. 同样将 Token 保存到仓库 A，用于仓库 A 发送部署信号给仓库 B。

2. 配置仓库 B（发送触发信号）

在仓库 B 的 action .github/workflows/deploy_trigger.yml 中写入：

name: Trigger Blog Build

on:
  push:
    branches:
      - main
    # 核心配置：只有当以下路径的文件发生变动时，才运行此工作流
    paths:
      - 'Blog/posts/**'      # 监听 blog posts 文件夹下所有文件，视情况调整

jobs:
  dispatch:
    runs-on: ubuntu-latest
    steps:
      - name: Send Repository Dispatch to Blog Repo
        run: |
          curl -X POST https://api.github.com/repos/用户名/仓库名/dispatches \
          -H "Accept: application/vnd.github.v3+json" \
          -H "Authorization: Bearer ${{ secrets.BLOG_ACCESS_TOKEN }}" \
          -d '{"event_type": "docs_updated"}'

它会在某特定文件夹变动时，发送一个 docs_updated 的消息

3. 配置仓库 A（接收信号并构建）

在仓库 A 的 action .github/workflows/blog_deploy.yml 中配置：

name: blog-deploy

on:
  push:
    branches: [ "main" ]
  repository_dispatch:
    types: [docs_updated] # 对应文档仓库的 event_type 钩子

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    # Steps represent a sequence of tasks that will be executed as part of the job
    steps:
      - name: Checkout engine repo
        uses: actions/checkout@v3
        with: 
          ref: 'main'
          fetch-depth: 0
          path: blog-engine # 指定检出到 blog-engine 目录
          
      # Checks-out your repository under $GITHUB_WORKSPACE, so your job can access it
      - name: Checkout docs repo
        uses: actions/checkout@v3
        with:
          repository: username/project # 文档仓库名称 
          token: ${{ secrets.BLOG_ACCESS_TOKEN }}
          ref: 'main'
          fetch-depth: 0
          path: blog-docs # 检出到 blog-docs 目录

      - name: Sync docs to build repo
        run: |
          # 确保 source 目录存在
          mkdir -p blog-engine/source
          # 把文档仓库对应文件夹内的所有内容，复制到 hexo 仓库 source 目录
          cp -r blog-docs/Blog/. blog-engine/source/
      
      - name: Setup node

      - name: Install dependencies

      - name: Setup environment

      - name: Deploy

博客文章顺序变化、更新时间错误的问题

由于我的博客中使用 mtime（文件修改时间）来展示更新日期，所以会有时间错误的问题。

可以尝试使用 git 的文件提交时间来修正文章的最后修改时间（以下为 AI 生成，仅供参考）

- name: Restore B repo Blog files modified time
  run: |
    # 进入文档仓库目录
    cd blog-docs
    # 遍历 B 仓库 Blog 下的所有 md 文件（包括子文件夹）
    git ls-files -z 'Blog/**/*.md' | while read -d '' doc_path; do
      # 获取文件的最后提交时间戳
      doc_timestamp=$(git log -1 --format="%ct" "$doc_path")
      # 匹配 A 仓库 source 目录下的路径（去掉 Blog/ 前缀）
      # 例：B 仓库 Blog/folder/article.md → A 仓库 source/folder/article.md
      target_path="../blog-engine/source/${doc_path#Blog/}"
      # 仅当文件存在时更新时间，避免报错
      if [ -f "$target_path" ]; then
        touch -d "@$doc_timestamp" "$target_path"
        echo "Restored time for: $target_path"
      fi
    done
    cd ..

后记

用上 Obsidian 之后，明显感觉到做笔记的频率变高了。在这个 AI 大行其道的时代，文字变得廉价，实现变得简单。保持写博客和记笔记，是用来提醒自己仍有学习能力的方式，可能也是某种无声抗议吧。
