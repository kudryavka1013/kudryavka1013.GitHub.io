WebAssembly 基础

发表于 2025-03-14 分类于 笔记 ， 前端

Any application that can be written in JavaScript, will eventually be written in JavaScript.

是什么

  • 是一种二进制格式的低级的类汇编语言，相比 JavaScript 具备更好的性能
  • 是一种新的编码方式，以 .wasm 格式存在，可以在 Web 浏览器或 Node 环境里运行
  • 可以作为 C/C++/C#/Rust 等语言的编译目标（通过某些工具将其编译为 WebAssembly）
  • 可以作为模块被 JavaScript 引入，和 JavaScript 一起使用

对于 JavaScript 来说，它相当于是引入第三方插件（相对于 JavaScript 来说），不可直接使用。引入它的目的并非是完全替代掉 JavaScript，而是一个补充，用于弥补 JavaScript 在某些高复杂度场景下的缺陷。

为什么

  • 前端的开发逻辑日益复杂，JavaScript 本身的性能限制了大型应用在 Web 上的运行效率
  • WebAssembly 能使得以各种语言编写的代码都可以接近原生的速度在 Web 中运行
  • WebAssembly 能让以前无法在 Web 上运行的客户端应用程序得以在 Web 上运行

大型项目中的应用

能够让一些计算量非常重的客户端应用在浏览器上相对流畅地运行，例如：

  • AutoCAD
  • Unity
  • Google Earth
  • Figma

怎么做

这里把 API 放到前面，感觉比较符合逻辑

JavaScript API

WebAssembly（下文简称 WASM）的一大用途就是作为一个库，提供一些函数，给 Web 上的 JavaScript（下文简称 JS）调用或者给通用的程序调用。将其看作是一个特殊的 module，我们只需要写一些胶水代码就可以像使用常规的 module 一样去使用它。

假定现在已经有了一个 .wasm 文件，它内部实现的功能类似于下边这段伪代码：

import { import_func } from js

function wa_hello() {
    import_func(`Hello WebAssembly!`)
}

export wa_hello

显然，这是引入了一个函数，同时向外提供一个函数。那么现在 JavaScript 中引入使用，可以分为以下三步：

  • 获取 .wasm 二进制文件，将它转换成类型数组或者 ArrayBuffer
  • 将二进制数据编译成一个 WebAssembly.Module
  • 外部传入该模块所需的 imports，并将其实例化；调用其实例 exports 提供的方法

基础的加载与调用

获取文件就像常规的 .js 文件一样，可以从网络（XHR、Fetch）下载、从本地文件读取、从 IndexedDB 获取。

编译和编译阶段，我们需要使用官方的 WebAssembly API 对文件进行编译，基本的几个方法如下：

  • WebAssembly.Module：构造函数，输入同步编译一个 WASM 模块
  • WebAssembly.Instance ：构造函数，同步实例化返回一个 WASM 模块

将以上几步结合起来，我们可以得到最基本的 WASM 实例化方式：

const importObject = {
    js: {
        import_func: (arg) => console.log(arg)
    }
}

const instance = fetch("simple.wasm")
    .then((response) => response.arrayBuffer())
    .then((bytes) => {
        const mod = new WebAssembly.Module(bytes);
        const instance = new WebAssembly.Instance(module, importObject);
        return instance;
    })

instance.exports.wa_hello(); // 调用 WASM 导出的 hello 函数

注意到 Instance() 有个额外参数 importObject，这是什么东西？

对于 WASM 模块来说，当需要引入 JS 函数、共享内存等特殊依赖时，就得从 importObject 获取。当然如果什么都不需要，importObject 给一个空对象 {} 就行了。

那要怎么知道它要什么东西呢？这会在对 .wasm 文件进行解读的时候一并讨论。现在先暂时跳过 importObject 这部分，假设我们已经对这个模块知根知底，并且所有东西都准备好了。

更好的使用方式

出于速度和效率的考虑，官方贴心地提供了异步的加载方式：

  • WebAssembly.compile()
  • WebAssembly.instantiate()
  • WebAssembly.compileStreaming()
  • WebAssembly.instantiateStreaming()

它们功能有重叠的部分，我们按需使用即可，下面一个个来介绍。

compile()

接收 bytes，然后异步编译一个 WASM 模块，会返回 Promise。

const module = await WebAssembly.compile(bytes);
instantiate()

可以接收 bytes 或编译后的模块，异步编译并实例化；如果传入的是模块，会直接实例化。

// 传入 bytes 会同时返回实例和模块
const { instance, module } = await WebAssembly.instantiate(bytes, importObject);
// 传入 module 则只有实例
const instance = await WebAssembly.instantiate(module, importObject);
compileStreaming() & instantiateStreaming()

对于流式方法，可以一边下载一边进行编译或实例化，它们直接对来自网络的原始字节流执行操作，从而无需执行 ArrayBuffer 步骤。但是只能接收 wasm Stream Promise，且请求头需要设置为 Application/wasm 。

目前一般都用这两个 API，性能比较高。

// 可以直接接收一个 fetch，返回一个模块
const module = await WebAssembly.compileStreaming(fetch('simple.wasm'))
// 同理
const { module, instance } = await WebAssembly.instantiateStreaming(fetch('simple.wasm'), importObject)

WASM interface

一个 Module 所声明的 imports 和 exports 可以通过静态方法 WebAssembly.Module.imports() 和 WebAssembly.Module.exports() 获取。

const module = await WebAssembly.compileStreaming(fetch("simple.wasm"));
const imports = WebAssembly.Module.imports(module);
const exports = WebAssembly.Module.exports(module);
console.log(imports, exports);

我们随便找个文件，解析后会得到类似下图的对象数组：

// imports
[{
    module: "my_namespace",
    name: "imported_func",
    kind: "function"
}]
// exports
[{
    name: "exported_func",
    kind: "function"
}]

更多可看 MDN 相关示例：导入 & 导出

上面的结果可以看出，WebAssembly 使用两级命名空间 module + name 来表示导入的模块。 kind 表示导入的类型，除了 function 外，还有 memory 、 table 等。导出则只有一层空间，统一从 exports 访问。

传入的 importObject 需要与 imports 的结构一一对应，以此为例，可以得到：

const importObject = {
    my_namespace: {
        imported_func: (p) => { your code }
    }
}

至于其它的类型，可以用 WebAssembly.Memory、WebAssembly.Table 等相应 API 生成实例并传入。

总结

以上就是 WebAssembly 的基本使用方法，并不算非常复杂。

其实 JS 主要就是写一些胶水代码，大部分实际运算都放在 WASM 里做，MDN 官网也有许多示例可供参考。要继续深入，则需要学习 .wasm 文件的结构以及了解相应的转换工具如 wasm2wat、Emscripten 等。

关于 WebAssembly 的前世今生可以看这里。有意思的是，目前前端生态的工具链，大部分都不是用 JS 实现的，开头那句话的 JavaScript 现在看来改成 Web 似乎更合适。
