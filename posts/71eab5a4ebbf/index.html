剪贴板那些事

发表于 2025-08-29 分类于 笔记 ， 前端

编程不能没有复制粘贴，正如西方不能失去耶路撒冷

浏览器上操作剪贴板的方式一般通过如下几种方式：

  • Clipboard Event：通过剪切、复制、粘贴的动作触发事件
  • Async Clipboard API：通过异步 API 直接操作剪贴板数据
  • execCommand：document 暴露的古早方法，不推荐再使用

Clipboard Event

通过操作剪贴板的动作触发回调函数，进而读取内容，调整后续动作

clipboardData 提供了 types 数组，指示剪贴板中所有数据的类型

const onPaste = (event) => {
    const {
        types
    } = event.clipboardData

    for (const mimeType of types) {
        const dataRawText = event.clipboardData.getData(mimeType);
    }
}

对于特殊的文件类型，是单独放在 files 属性中的，可以作为数组读取

const fileList = Array.from(e.clipboardData.files);

Async Clipboard API

navigator.clipboard 提供 read 、 readText 和 write 等方法

readText

最简单的方法，读取纯文本内容，没有什么特别的

const text = await navigator.clipboard.readText();

read

区别于 Event 文件类型会单独存放在 files 中， read 方法会读取包括图片、文件、富文本在内的数据，可以用 blob 形式去读取

同理，可以使用 types 字段得到剪贴板中的数据类型，然后使用 getType 方法去读取内容

const clipboardItems = await navigator.clipboard.read();
// 通常只有一个 clipboardItem
const items = [];
for (const clipboardItem of clipboardItems) {
    const blobs = [];
    for (const mimeType of clipboardItem.types) {
        const blob = await clipboardItem.getType(mimeType);
        const dataRawText = await blob.text();
    }
    blobs.push({
        mimeType,
        dataRawText
    });
}
items.push(blobs);

write、writeText

write 可以向剪贴板中写入内容，我们需要构造 ClipboardItem ，写入 MIME 类型和数据

const blob = new Blob(['Hello, world!'], {
    type: 'text/plain'
});
const clipboardItem = new ClipboardItem({
    'text/plain': blob
});

navigator.clipboard.write([clipboardItem])
    .then(() => {
        console.log('内容已写入剪贴板');
    })
    .catch(err => {
        console.error('写入失败', err);
    });

还有一个相对简单的 writeText ，就仅是写入文本

await navigator.clipboard.writeText('要写入剪贴板的内容');

其它问题

为什么 navigator.clipboard.read() 无法获取自定义 MIME 类型的数据？

事件触发，是操作系统层面的信号，可认为是由用户主动授权的操作，浏览器一般会允许读取所有能提供的类型。

但异步 API 读取，由于可以被 JS 直接发起，如果被滥用会有较大安全风险，因此受到安全策略的限制。
实际上，异步 API 一般只会提供标准的类型（text/plain，text/html 等），我们手动写入的自定义数据是不会被返回的，甚至连 application/xxx 这种格式也不会返回。

同时使用同步和异步 API？

当同时使用 navigator.clipboard.read() 和操作 Event 时，浏览器会优先处理异步剪贴板数据，部分浏览器会清空或锁定同步的 e.clipboardData ，导致在同一个 paste 事件里无法再通过 e.clipboardData 读取到原始数据。当然一般情况下，没有这样做的需要。
